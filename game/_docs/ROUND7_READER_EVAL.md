## 0. 两个「思考档」到底是怎么配的（如实交代）

平台事实：`create_agent` **没有「思考强度」参数**，能控的只有任务描述、约束密度、交付格式与 agent 名字。所以本轮不是"平台低档 vs 平台高档"，而是**用 prompt 层代理两档读者**，报告里不许写成"平台支持档位"：

| | 读者 A（低思考档） | 读者 B（高思考档） |
|---|---|---|
| 人设 | 普通玩家，随手读一遍 | 较真玩家 + 剧情校对 |
| 任务约束 | 11 项固定问题，凭直觉答，不许写长分析 | 12 项 + 每条判断必须带**原句 + 章号**，逐章观感、menu 计数、硬伤清单 |
| 交付格式 | 玩家口吻、无术语、5 句总结 | 证据表、逐章清单、硬伤逐条论证 |
| 读法 | 只沿选定分支读 | 主走白砚线，另**快读**另两线做对照（承认越界，用于交叉核对，不计入"周目"） |
| 串流关系 | 先跑，跑完才派 B | 后跑，**未接触 A 的任何输出**；两份报告在汇总前互不可见 |

两人的共同点比设计预期更值钱：**都给了 7/10，都批"环境重复 + 秘密收一半 + 选择代价弱"**，说明这不是单个人口味。

> **最要紧的一条**：两人各自读 7 万字，体感都只有 **2.5–3.5 小时**，而不是我们按 200 字/分算出的 6.0 小时。也就是说"字数→时长"的换算是**偏乐观的**：读者并不逐字慢读，跨章重复的静态描写被他们自动略过。离用户要的 6–8h，缺口不在"再加多少字"，而在**节拍密度与信息增量**（下面 §5 给 D 批建议时用这条）。

## 5. 对 D 批的输入（含 6–8h 缺口的判断）

**先说时长**：读者体感 2.5–3.5h，字数换算 5.0h（240 字/分）/ 6.0h（200 字/分）。三个数的落差说明：

1. 现在的 71,773–72,126 字/周目，**在玩家真实阅读速度下大约只值 3 小时上下**（读者会跳读重复的景物段）。
2. 因此"再按 C 批的做法加 1.2 万字/组容器"**换不来等比例的时长**——读者对"没有新增信息的环境段"是直接跳过的。
3. 若目标真是 6–8h，D 批应该改**结构**而不是只加字：独行线专属章节（solo 现在是 ch25 一刀封死，等于少一整条线的内容）、三条个人线的**互斥内容**（走 A 线看不到 B 线的东西）、以及"选择真的分叉"的支线体量。

**D 批建议（按性价比排序，均不含"注水"）**：

1. **加一道跨章数字/物件的机器校验**（脚本级，不属禁改范围）：把"针剂/干粮/绳子/天数/人物旧伤部位"这类可数物件做成一张表，逐章正则抽取值，对不上就报错。上面 4 条硬伤里至少 3 条能被它一次抓出来。
2. **给 solo 一条真正的内容线**：现在 solo 只在 ch25 分支上被锁死成 `sealed`，玩家少了 6 章左右的内容却没有任何替代内容。这是最便宜的"加时长"——不用新写 4.8 万字，只要把 ch16–24 的 solo 版本补 3 章（每章 4,000 字量级）。
3. **把"秘密落半步"补齐**：蓝羽半个字、白砚倒下的那个人、青岩被刮的署名，各补 150–300 字的具体交代（一个名字/一件遗物/一次对照），读者的"没收完"抱怨会直接消掉一半。
4. **删段比加段更值**：读者两次独立点名跨章景物重复（ch08/ch11/ch15/ch21/ch26）。删掉 3,000–5,000 字的同义景物段，读者体感反而更长（因为不再跳读），且省下的预算可以投到 2、3 两条。
5. **（可选，需用户拍板）真结局门槛可见化**：B 明确指出 `trust_shiqi` 是"漏了一个无提示开关"——ch15 三个选项表面都是"进门方式"，没有一句提示"情报换信任"会决定结局。要么在 ch15 文案里加一句钩子，要么把该条件在 ch25 前给一次回声。**这属于设计判断，不在本轮擅改范围。**
6. **不建议**：继续按"每组容器 1,200–2,000 字"批量加共同线。两人都证明共同线的瓶颈是重复而非字数。

## 6. 本轮读者评估的边界（没验到的）

- 两人都是**读文本**，不是开游戏点鼠标（本环境无桌面控制，见 `ROUND7_PLAYTEST.md` §1）。因此 UI 手感、字体渲染、名字牌缺字、音乐氛围，**读者评估完全没覆盖**。
- B 为了对照快读了未选的两条线，严格意义上不完全是"单周目沉浸"，其"节奏"判断含少量越界信息。
- 两人都没读设计文档，所以他们的"设计意图"判断是玩家视角的推测，可能与 `ROUND7_SWEET_KNIFE.md` 的账本不一致——这恰好是我们要的东西（玩家看不见账本）。
